# 01 · 设计方法：从「朋克分支」到 LiveSkin 皮肤家族

---

## 一、三级映射

LiveSkin 的模型是 **family / variant / preset** 三级。朋克资料天然也是分层的，两边几乎一一对应：

| LiveSkin 层级 | 朋克资料里的对应物 | 判断依据 |
| --- | --- | --- |
| **family 家族** | 一个朋克**分支** | 有自己独立的**时代物质底座**：能源、材料、界面器物三者与其它分支不重合 |
| **variant 皮肤** | 该分支内部的**子风格取向** | 共用同一底座，差别在**焦点、布光、气氛、场景** |
| **preset 档位** | 同一取向的**强度档** | 不改视觉语言，只改量：通透、磨砂、动效、饱和度 |

这条映射的判据不是「感觉像不像」，而是**物质底座是否相同**。举例：

- 装饰朋克（decopunk）与柴油朋克共用战间期的 Art Deco 都会、同一批世博会档案 → 同一个 family，另一个 variant。
- 磁带未来主义与赛博朋克共用「80 年代技术想象」，但器物完全不同（米白塑料机箱 / 荧光绿终端 / 机房日光灯 vs 霓虹雨夜 / 义体 / 城寨）→ **不同 family**。

---

## 二、三层各放什么

### family 层（共享）

- **调色板骨架**：整套 `--dsw-alias-*` 的映射，由家族参数派生。这是家族最大的一层，也是「一眼认出是这一支」的来源。
- **材质语言**：底纹、描边、阴影、圆角、高光的方向与硬度。
- **公共参数**的声明（见第四节）。
- **家族级 CSS**：所有 variant 都会用到的结构（面板、滚动条、选中态、`body::before/::after` 的层）。

### variant 层（差异）

**只写这个取向独有的东西**，其余一律从 family 继承。典型内容：

- 壁纸 / 背景图层（作为 `wallpaper` enum 选项的 `css` / `cssDark` 载荷）；
- 该取向的标志性动效（若与家族其它 variant 不同）；
- 对继承参数默认值的覆盖，写在 `defaults` 里（例如 `"glass": 72, "wallpaper": "rain"`）；
- 该取向专属的新参数声明。

> **反模式**：variant 里整段复制 family 的 token 块。这会让「改一处、忘一处」成为常态。variant 的 `skin.css` 应当短，短到能一眼看完。

### preset 层（档位）

同一 variant 的强度档。建议每个家族统一提供三档，语义跨家族一致：

| preset id | 名称 | 语义 |
| --- | --- | --- |
| `restrained` | 克制 | 氛围压到最低，可读性优先，适合长时间工作 |
| `standard` | 标准 | 该 variant 的设计意图原样呈现 |
| `cinematic` | 浓烈 | 氛围拉满，适合展示；允许牺牲一点可读性 |

家族可以在 `family.json` 里定义这三档（自动继承给所有 variant），variant 按 id 覆盖同名的那一档。

## 三、命名规范

| 对象 | 规范 | 例 |
| --- | --- | --- |
| family id | `<分支>Family`，首字母大写，无分隔符 | `SteampunkFamily` |
| variant id | 大驼峰，指向**场景或材质**而非抽象情绪 | `BrassAndSteam`、`RainyNeon`、`BeigeTerminal` |
| preset id | 全小写，三档固定 | `restrained` / `standard` / `cinematic` |
| 参数 key | 小驼峰，语义化 | `patina`、`scanline`、`wetness` |
| CSS 变量 | 由 key 自动派生，`--ls-<kebab>` | `--ls-bubble-amount` |
| 家族专属变量 | 允许在 CSS 里定义中间量，同样以 `--ls-` 开头 | `--ls-patina-alpha` |

**variant 命名禁用**：`Dark`、`Light`、`V2`、`Alt` 这类无信息量的名字。名字要能让人在列表里不看描述就知道是什么。

## 四、参数设计

### 公共参数（每个家族都必须有，语义与取值范围跨家族一致）

这五个参数的**存在意义是跨家族的心智一致性**——用户在赛博朋克里学会「通透度」，到蒸汽朋克里还是同一个意思。

| key | type | 范围 | 说明 |
| --- | --- | --- | --- |
| `glass` | number | 0–100 | 面板遮住底纹的程度，越大越透 |
| `blur` | number (`px`) | 0–24 | 浮层磨砂强度 |
| `accent` | color | — | 强调色：按钮、链接、选中态 |
| `intensity` | number | 0–100 | 氛围总强度，缩放该家族自己的标志性效果 |
| `motion` | boolean | — | 标志性动效开关（关掉必须不留合成层） |

### 家族专属参数

每个家族 2–4 个，用来表达这一支独有的可调维度。**必须是真正有视觉意义的**——不能为了「显得可配置」而设。示例：

| 家族 | 专属参数（草图） |
| --- | --- |
| Steampunk | `patina` 铜绿、`brass` 黄铜亮度、`pressure` 蒸汽脉冲 |
| Dieselpunk | `grain` 胶片颗粒、`chrome` 铬银高光、`noir` 强反差分光 |
| Atompunk | `radiation` 放射色饱和度、`era` 50s/60s 切换（enum）、`travel` 按钮行程 |
| Cyberpunk | `neon` 霓虹强度、`rain` 雨幕倒影、`scanline` CRT 扫描线 |
| Biopunk | `wetness` 湿润感、`pulse` 生物脉冲、`tissue` 组织透明度 |

> 上述为**草图**，最终以各分支规格文档为准。

### 参数设计的硬规则

1. 每个参数都必须被 CSS 真正引用（否则是死旋钮，`[5]` 段会报错）。
2. 每个参数的默认值必须产出该 variant 的**设计意图**——用户不动任何滑杆时就该看到成品。
3. 取值范围要能覆盖「几乎没有」到「非常明显」，默认值通常落在 55–70 区间。
4. **不设**纯装饰性参数（例如「让圆角大 2px」），除非它能显著改变观感。

## 五、每个家族的交付物清单

```
../plugin/skins/<FamilyId>/
  family.json                 家族声明：name / params / presets / styles / accent
  base.css                    家族层：整套 token 映射 + 材质语言 + 结构
  <VariantA>/
    skin.json                 variant 声明：name / description / defaults / styles
    skin.css                  variant 层：只写差异
  <VariantB>/…
  <VariantC>/…
```

对照本目录下的 `<序号>_<分支>.md` 规格文档实现。规格文档必须给出：

- 家族层要映射的 token 清单与取值方向；
- 每个 variant 的壁纸图层、材质、动效；
- 三档 preset 的具体数值；
- 该分支的雷区与规避方式。

---

## 六、防止七个家族互相抄

家族数量一多，最容易出现的失败是「同一套骨架换了七次色」。每个家族必须在**材质语言**这一层做出不可互换的东西——换色换不出来的那种：

| 家族 | 不可互换的材质签名（举例） |
| --- | --- |
| Steampunk | 铜的**氧化渐变**：从亮铜到铜绿的多段渐变，配缝线与铆钉点的重复纹理 |
| Dieselpunk | 胶片的**颗粒与划痕**：低透明噪点叠层 + 单侧硬光，界面像被重新打光的新闻片 |
| Atompunk | 镀铬的**镜面高光带**：硬边、高对比、可预测的反光角度；完全不做旧 |
| Cyberpunk | 雨幕的**糊光**：大半径 bloom + 面板底部的竖向倒影 |
| Biopunk | 组织的**半透与脉动**：不规则的圆角与缓慢的呼吸式明度变化 |
| Cassette Futurism | 塑料的**哑光与模具缝**：无渐变的平坦色块 + 1px 内嵌亮边 |
| Solarpunk | 手工的**不规则**：非整数圆角、编织纹理、日照方向的暖渐变 |

**验收方式**：把七个家族的界面缩成 64×64 缩略图并去掉颜色，仍然能认出哪个是哪个——认不出就说明材质签名没做出来。
