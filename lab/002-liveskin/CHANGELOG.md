## [1.2.1] · 2026-09-13

面板的分类行改了两处：把排序依据显示出来，并把标签列从定宽右对齐改成左对齐的共用网格。

### 新增

- 分类的**排序依据**写进宿主常量并显示在面板里（`朋克美学` / `按光谱轴`、
  `千禧美学` / `按血缘与年代`、`星际争霸` / `按种族`）—— 只写分类名，
  用户看不出这一行是按什么排的。与分类和 `order` 一样，它是数据而不是面板文案。
  依据**换行显示在分类名下方**：并排会按最长的那一条撑宽标签列，而依据只是注解，
  不该挤占横向空间。

### 修复

- 面板分类行的左侧留白：标签原本定宽 88px 且右对齐，短标签左边会空一块。
  改为**所有分类行共用一个网格**（行用 `display:contents` 参与外层网格），
  标签列宽度取全分类里最宽的那个（现在是分类名，依据在下一行）、文字左对齐 ——
  各行 chip 的左边缘因此是对齐的，而不是每行各自缩进。

## [1.1.1] · 2026-09-12

一次修正版：修掉 11 支变体的壁纸与调色板矛盾（那是**同一个 bug 的最大一批**），
把 `@body` 探针扩到能读壁纸，并给家族加上分类、面板按分类分行。

### 新增

- **家族分类**：`family.json` 新增必填的 `category`，面板里按它把家族**分成几行**
  （一行一类），行序由宿主常量 `CATEGORIES` 给出而不是在面板里排 —— 那是数据不是显示。
  三类：`朋克美学`（七个朋克家族，时间轴）、`千禧年美学`（`FrutigerAeroFamily`，
  紧挨时间轴右端）、`星际争霸`（人族 / 虫族 / 神族，不在轴上）。
  分类漏写或写成没声明过的值会在目录册里报诊断 —— 否则它会悄悄混进别的行，
  而面板上没有任何东西提示这件事。

### 修复

- **11 支变体的壁纸与自己的调色板矛盾**。变体把壁纸写在无档位的 `body` 上、而且用的是
  **不透明色** —— 不透明壁纸会把**另一档**的页面直接翻成相反极性，而 token 是按档走的：
  亮色档拿到暗壁纸时深色正文压在暗页面上，对比度掉到 1.0–1.2:1。
  受影响的是 `AtompunkFamily` 四支（**暗色档**拿到亮壁纸）、
  `CassetteFuturismFamily/{ControlRoom,MagneticNight,TapeDeck}` 与
  `SolarpunkFamily/{Dawnlight,Glasshouse,Terracotta}`（**亮色档**拿到暗壁纸）。
  改法：壁纸按**自身颜色的极性**归到对应的档，另一档给一层同色相的 alpha 淡洗 ——
  保留这一支的色调，又不可能翻转极性。
- **`FrutigerAeroFamily/FrutigerAero` 的次要文字与链接压在壁纸的草地绿带（约 `#5fb832`）
  上不达标**（2.70:1 / 4.43:1）。按「底色守氛围、文字层强制达标」调文字层：
  `label-secondary` `#2d617a` → `#1f4a5f`，链接混色 42% → 34%。

### 变更

- **`@body` 探针扩展到壁纸**。它原来只读 `background-color`，而 `background-image`
  可以是不透明的 —— 那时页面的实际颜色完全由它决定，底色只是个被盖住的底，
  于是上面那 11 处全被漏掉。现在按 CSS 的层序（先写的在上层）自底向上叠，
  取**不透明色标**作为页面颜色候选。
  半透明层不算：页面偏成什么色取决于它盖在哪、盖多大，静态解算看不出几何，
  当整页颜色会造出一堆假阳性（某个变体左上角 72×72 的 HUD 角标会让整页被判成琥珀色）。

  证伪时踩到一次值得记的坑：第一次注入违规用的是无档位的 `body`，结果被已有的
  `body:not([data-ds-dark-theme])`（(0,2,2) > (0,1,2)）按特异性压掉了，
  证伪自然不变红 —— **注入违规的方式本身也要符合层叠规则**，否则证伪是假的。

## [1.1.0] · 2026-09-12

新增**星际争霸的三个种族家族** —— 3 个家族 × 4 支 = 12 套皮肤，**每一支都支持亮暗两档**。
目录册从 8 家族 31 支扩到 **11 家族 43 支**。

### 新增

- **`TerranFamily`（人族）** 4 支：帝国前哨 / 玛萨拉黄昏 / 幽灵特工 / 兵营甲板。
  工业与尘埃 —— 冲压钢板、橄榄绿、琥珀仪表背光；光是**均匀的顶灯**，不为戏剧性服务。
- **`ZergFamily`（虫族）** 4 支：虫巢 / 育雏池 / 利维坦 / 菌毯。
  几丁质与菌毯 —— 没有一条直线，高光向内汇聚，**没有边界**。
- **`ProtossFamily`（神族）** 4 支：艾尔神殿 / 枢纽网格 / 虚空碎片 / 凯达林水晶。
  大理石与水晶 —— **不模糊**的锐利辉光、悬浮的金色细线，光没有来源。
- 规格文档 `docs/11_星际争霸.md`。
- 家族色板生成器 `scripts/gen-family.py`：以一个已通过全部验收的家族为**结构模板**，
  只做颜色替换，token 集与函数形状原样继承；规格没覆盖到的颜色字面量会直接报错，
  不静默放过。
- **光照方向轴从七个位置扩到九个**：人族补上「均匀顶灯」（面与反射之间），
  神族补上「锐利无模糊」（向外 bloom 与向内之间），虫族把「向内」推到「无边界」。

### 修复

- **宿主新鲜度判据改用内容哈希**。原先比的是 `lib/index.js` 的 mtime，两个方向都会错：
  **假阳性** —— 内容相同的重写（`git checkout` / `git reset` / 编辑器保存 / `touch`）
  改了 mtime 却没改代码，于是「明明重启过了却还被判成需要重启」；
  **假阴性** —— 只比单个文件，会漏掉另一半宿主代码 `appearance.js` 的改动。
  现在宿主上报 `hostSources` 与 `sourcesHash`，验收台按同样算法比对，
  并核对那份清单与 `lib/` 下的实际文件一致 —— 以后新增宿主模块忘了登记会直接报错，
  而不是静默漏检。

### 说明

- 三个种族**不排进朋克时间轴**：它们是同一个宇宙里的三种文明形态
  （人族拼出来、虫族长出来、神族想出来），不是「曾经的未来」。并列而不排进轴里，
  是为了不让那条时间轴被稀释成「一堆科幻主题」。
- 三个种族**没有卷内资料**（`doc/punks/` 不涉及游戏），全部由外部观察推断。
  所有皮肤都是**纯 CSS 的美学演绎**：零外部资产、不出现阵营徽标与商标图形、
  不向界面注入文字。
- **已知问题（未修）**：既有变体里有 28 个在无档位的 `body` 上铺了**不透明**壁纸，
  其中 4 个与自己的调色板矛盾 —— `AtompunkFamily/DuckAndCover` 与
  `CassetteFuturismFamily/{ControlRoom,MagneticNight,TapeDeck}` 在**亮色档拿到暗壁纸**。
  验收台的 `@body` 探针只读 `background-color`，看不到壁纸这一层，所以没报出来；
  判据要扩到 `background-image` 才能守住。新增的三个种族家族只使用**带 alpha** 的壁纸，
  不受影响。

- **宿主新鲜度判据改用内容哈希**。原先比的是 `lib/index.js` 的 mtime，两个方向都会错：
  **假阳性** —— 内容相同的重写（`git checkout` / `git reset` / 编辑器保存 / `touch`）
  改了 mtime 却没改代码，于是「明明重启过了却还被判成需要重启」；
  **假阴性** —— 只比单个文件，会漏掉另一半宿主代码 `appearance.js` 的改动。
  现在宿主上报 `hostSources` 与 `sourcesHash`，验收台按同样算法比对，
  并核对那份清单与 `lib/` 下的实际文件一致 —— 以后新增宿主模块忘了登记会直接报错，
  而不是静默漏检。

## [1.0.0] · 2026-09-12

首个正式版本。三级模型（family / variant / preset）、8 个家族 31 套皮肤、参数化实时调节、
亮暗两档支持与面板标记都已在真实 DSH 上跑通并逐条验证（验收台 63 项断言）。
2026-09-11 的初始提交已包含插件本体、三级模型、七个朋克家族的首版与整套设计文档；
本节记录 1.0 相对那一版补齐的东西。

### 新增

- **设置面板**标出「正在使用」的家族与皮肤：家族按钮与皮肤卡片各自带标记，与「正在查看」
  区分开；浏览别的皮肤时状态栏出现「回到当前」，一键切回生效的那一套。
- **皮肤档位徽章**：每套皮肤标注它在亮/暗两档分别是什么样 ——「亮 / 暗 跟随系统」
  或「仅暗色观感 / 仅亮色观感」。档位由宿主读皮肤自己的 CSS **推导**，不是手写声明。
- **零件级 token 的暗色对应生成器** `plugin/scripts/gen-dark-parity.py`：`--check` 报每个家族
  还缺哪些 token，`--emit <Family>` 打印建议值。规则可复核，不含猜测。
- 验收台新增断言：`@body`（正文压在实际页面底色上）、链接对比度、
  每套皮肤的档位推导、面板状态规则的组合态纪律。
- **版本号在运行时可问**：`/health` 与目录册都带 `version`，设置面板标题显示
  `LiveSkin <版本>` —— 否则「线上跑的是哪一版」只能靠 git tag 猜。

### 修复

- **暗色档里亮底压浅字**（用户报告）。根因是选择器特异性：皮肤浅色块写在
  `html[data-live-skin] body`（0,1,2）上，压过官方暗色块 `body[data-ds-dark-theme]`（0,1,1）
  —— 皮肤在浅色块里声明、却没在暗色块里重写的 token，在暗色档拿到的是浅色值。
  输入框、代码块、列表选项、高亮整片看不清；`AtompunkFamily` 更彻底，`body` 底色没重画，
  整页只有 1.04:1。
- **链接对比度**：强调色是为填充与描边挑的，直接当正文链接用，橘色在米白页上只有 3.1:1、
  亮绿在强制亮色的变体上只有 1.3:1。改为相对强调色向页面反方向混合（亮底压深、暗底提亮），
  极性跟着**页面**走而不是跟着模式名走。
- **强制单一观感的变体在另一个档失效**。`body, body[data-ds-dark-theme]` 这种写法里，
  `body`（0,1,2）会在亮色档输给大类的浅色块 —— `DarkAero`、`Overgrown`、`Cleanroom`、
  `BeigeTerminal` 都受此影响。改为成对使用 (0,2,2) 的选择器，并各自重画 `body` 底色。
- **家族按钮选中态深底深字**（用户报告）：「使用中」标记只该加描边，却把选中态钉住的白字
  覆盖成了深墨色。两条规则同特异性、源码在后者获胜。

### 变更

- **家族与皮肤的两档约定**（`docs/10_工程约束与验收.md` 的 C12）：亮色默认的家族把
  浅色块限定为 `body:not([data-ds-dark-theme])`，参数派生量 `--ls-*` 留在两档共用的规则里；
  强制单一观感的变体两个档成对声明；两档都要重画 `body` 底色。
- **验收台的 C4 重写**：旧版只查 5 对手写探针，且皮肤没声明就跳过 ——「皮肤没写」被当成
  「没问题」，而真相是官方值生效。现在回落到官方调色板、按**特异性**而非文档顺序决胜、
  逗号列表按分支判定、半透明与渐变合成到页面底色上再比。
- **宿主新鲜度判据**改为通用形式：宿主在 `/health` 上报自己**加载那一刻**读到的文件 mtime，
  与磁盘现值不一致即判失败。旧探针只认一次历史改动的行为，宿主已经旧到不认识新字段时
  它仍然显示绿色。
- `AtompunkFamily` 与 `SolarpunkFamily` 的暗色块由 28 / 20 条补齐到 95 条；
  其余五个家族的默认块本身就是暗色，未改动。
- 版本号 `0.1.0` → `1.0.0`。

### 说明

- **改动何时生效**：`plugin/skins/**` 与 `plugin/lib/client.js` 刷新页面即可；
  `plugin/lib/index.js`、`plugin/lib/appearance.js` 属宿主半边，**必须重启 DSH**。
- 对比度数值均由验收台静态解算得出（含半透明与渐变的合成），不是肉眼估读；
  但「看上去对不对」仍需人工在设置面板里逐支切换确认。

## [初始提交] · 2026-09-11

- 插件本体 `plugin/`：`family.json` + `base.css` 定义大类，`skin.json` + `skin.css`
  定义小类，预设按 id 合并；参数 schema 支持 `number` / `boolean` / `color` / `enum` / `text`，
  自动映射到 `--ls-*` 变量；HTTP 面以 `/api/live-skin/v1` 为前缀。
- 七个复古未来朋克家族共 28 套皮肤，外加既有的 `FrutigerAeroFamily` 3 套，合计 8 家族 31 套。
- 设计文档 `docs/`：家族总表、光谱轴、材质签名登记、七份分支规格，以及工程约束 C1–C11。
- 冒烟测试台 `test/run.mjs`。
- 前身 `archive/aero-skin-build/`：给皮肤中心（skin-center）生成 Frutiger Aero 三支配方的
  构建脚手架，用的是另一套 schema。
